## C1 — IDOR probes fire live credentials at out-of-scope hosts (CRITICAL, OPEN)

**Where:** `oracle_auth_session.py:302-355` (`build_idor_probes`), called from
`oracle_hunter.py:3983` with no scope gate between generation and verify.

**PoC (executed, not theorized):**
```python
h = DualAccountHarness(target_domain="victim.com", ...)
h.account_b.token = "Bearer ATTACKER_LIVE_TOKEN"
seams = [{"check": "curl -s 'https://victim.com/api/orders/ord_12345'",
          "assertion_a": "a",
          "assertion_b": "see https://evil.com/api/orders/ord_99999 and https://victim.com/api/orders/ord_12345"}]
probes = h.build_idor_probes(seams)   # → 2 probes, one aimed at https://evil.…
# probe output: evil-emitted=True  (/tmp/probe_idor.txt)
```
The corpus scraped is `check + assertion_a + assertion_b` — assertion text is
LLM-written. Any hallucinated `https://…/<id>` in prose becomes a live probe.
The `_id_pattern` only demands an ID-shaped path segment, not an in-scope host.

**Impact:** live Account B token sent to an attacker-controlled or third-party
host (credential disclosure), plus out-of-scope probing (program violation).
This is LOGIC_AUDIT CRITICAL #2, still present verbatim.

**Fix direction (after review):** parse host from each candidate URL; require
`scope_gate.is_in_scope(url)` AND host ∈ recon-verified hosts before building
the probe; source URLs from `check` fields only, never assertion prose; add
`test_idor_scope_gate.py` with evil.com / lookalike-host cases.

## C2 — live attacker token stored verbatim in seam cards (CRITICAL, OPEN)

**Where:** `oracle_auth_session.py:276-300` (`build_curl_probe` embeds
`Authorization: Bearer …` + cookies into the returned string, stored as seam
`check`), flowing to terminal display, `sessions.json`, report JSON, and cloud
LLM prompts (`oracle_hunter.py:3988`, `_finalize_verify`).

**PoC:** same probe as C1 — `token-in-storage=True`: every emitted probe
contains `Authorization: Bearer ATTACKER_LIVE_TOKEN` in plain text.

**Impact:** credential-at-rest + credential-to-third-party (any PoC/triage
prompt ships the secret to OpenRouter/Claude/Gemini). `_redact_creds` exists
for *display* but the stored canonical string still holds the secret, and any
missed call-site leaks it.

**Fix direction:** store checks with `__ACCOUNT_B_AUTH__` placeholder; inject
real headers only inside `_run_check` at execution time (the `-K 0600` config
pattern already exists there); scrub on load; test that no persisted artifact
contains the token.

## H1 — template code lens blind to smart contracts (HIGH, OPEN)

**Where:** `oracle_seam_templates.py:472`:
```python
_CODE_EXTS = (".py", ".js", ".ts", ".jsx", ".tsx", ".php")
```
`*_CODE_EXTS` feeds `_t_code_mirror` and `_t_code_deathless`. `.sol`,
`.cairo`, `.rs`, `.go`, `.java`, `.move` are never walked.

**PoC:** repo with `Vault.sol` + `app.py` → `scan_template_seams` returns
**0 cards** although a privileged `withdraw` with no guard sits on disk.
`.sol in _CODE_EXTS` → `False` (`/tmp/probe_exec.txt`).

**Impact:** on any Cantina/Code4rena/Sherlock/Immunefi target the no-LLM template
layer contributes zero. The engine underneath *does* have Solidity support
(`solidity_extractor.py` + `solidity_matcher.py` in invisible_seam), but
Oracle's own template layer ignores the language entirely.

## H2 — slither/forge/cast/anvil/aderyn installed but never called (HIGH, OPEN)

All five resolve on this box (`slither`, `forge 1.5.1`, `cast`, `anvil`,
`aderyn 0.1.9`), yet `grep` over `oracle/*.py` shows zero call sites — no
`forge build`, no `forge test`, no `slither`, no fork-replay, no `cast call`.
So even where the NatSpec matcher fires, there is no build, no test, no
on-chain proof: a Solidity seam can never become an executed, confirmed,
submittable finding through Oracle today.

**Fix direction (H1+H2, after review):** extend `_CODE_EXTS` with
`.sol/.cairo/.rs/.go/.java/.move`; add Solidity-aware template detectors
(unchecked `call`, missing `onlyOwner` vs NatSpec, reentrancy shape,
`tx.origin`, unguarded `selfdestruct`/`delegatecall`); add a
`solana/solidity proof` stage — `forge build` → `forge test` → `anvil`
fork-replay producing executed output as `check_output`; record tool versions
in the report.

## H3 — state-changing bugs can never CONFIRM, even on testnet (HIGH, OPEN)

**Where:** `oracle_hunter.py:1972-2001` (`_run_check` executor).

**PoC:** `curl -X POST …` → `[BLOCKED] check rejected: unsafe HTTP method`
(`rc=1`), even though the target is `127.0.0.1:8765` and the flaw it would
prove (Flaw 7: coupon on a PAID order, `bad_code_app.py:173-186`, and the
`apply_discount` POST) is a first-class seeded bug. Meanwhile `validate_check`
 downgrades PROD POST→GET with `ok=True` (M2), so the two gates disagree: one
silently rewrites, the other hard-blocks.

**Impact:** the entire state-manipulation class (price/coupon/role mutation —
the bugs that actually pay) is unreachable end-to-end. The testbeds seed it;
the executor refuses it.

**Fix direction:** allow POST/PUT/PATCH/DELETE through `_run_check` iff
`is_testnet` (or staging/sandbox/loopback asset) is true, with explicit
operator consent flag; keep the hard block for production; thread the flag
from `verify_seams` into `_run_check` (today the flag exists at validate time
but never reaches execution).

## H4 — empty program cache saved unconditionally (HIGH, OPEN)

**Where:** `oracle_programs.py:1793-1798` — `_save_cache` writes whatever it is
given, including `[]`. Correction to my own earlier probe note: `"count":
len(programs)` is bookkeeping, not a guard — there is no `if not programs:
return/raise`. A fully-failed scrape still poisons the cache and the next 24h
(`_load_cache`, `age_h > 24`) serve the empty result as complete.
LOGIC_AUDIT CRITICAL #3, unchanged.

## H5 — scope fallback to bare target name (HIGH, OPEN)

Unknown program → `_scope_from_programs` returns `{}` (probe-verified); the
gate then falls back to the raw target string, and non-HackerOne platforms
ship programs with no `structured_scopes` at all. Net effect: on exactly the
long-tail platforms (Cantina/Code4rena/Sherlock — i.e. the smart-contract
targets) the "scope wall" is a guess, not a wall. Intake (`cmd_hunt` §1a) tries
to backfill, but a failed backfill warns once and continues recon anyway.

## Mediums (all OPEN, all probe- or read-confirmed)

**M1 — static-only findings wear the CONFIRMED label.** `_SELF_CONFIRMING`
(`oracle_code_seam.py:291-329`) stamps `verdict=CERTAIN` with
`check_output="Extractor confirmed: … — no live server needed"`, and
`_audit_evidence_tier` (used by the audit report) promotes *any* non-empty
`check_output` to tier CONFIRMED. The hunt path (`oracle_hunter.py:4008-4017`)
holds the line correctly (CERTAIN + non-empty output → confirmed), which means
the audit path over-claims relative to the hunt path's own rule: extractor ran
≠ check executed. My Solidity probe demonstrated it: 1 seam,
`[PARADOX/CERTAIN]`, `check=''`, `check_output=''` — and sibling claim types
would carry the synthetic "Extractor confirmed" string as evidence.

**M2 — PROD POST→GET downgrade verifies with `ok=True`.**
`validate_check` on a production host rewrites
`curl -X POST --data … https://api.victim.com/orders` →
`curl -X GET https://api.victim.com/orders`, returns `(True, …)` with reason
`PRODUCTION SAFE MODE…`. A downstream CONFIRM from the GET never exercised the
mutation. Only an `_info` line marks the rewrite. Gate should mark downgraded
checks non-confirming (LOGIC_AUDIT said the same; unchanged).

**M3 — `_parse_seams` filler assertions.** Free-text small-model output with no
A/B gets `"Service assumes authentication or boundary is enforced."` /
`"Wire reality exposes endpoint…"`. Benign intent (keep the card, let Gate 4
kill it), but the filler now *looks* like a claim in reports. Gate 4
(`assertion_a_source` required) does reject these — verified: `no-source →
REJECTED` — so the mitigation holds, but the filler should be labeled
`synthetic-fallback` so no consumer mistakes it for model output.

**M4 — dead check text.** Template code cards emit `grep -rn …` checks; some
`manual_check` strings contain `| head -c 200`. `_run_check` rejects both
(non-curl binary; `|` metachar). These cards can never execute through the
pipeline — they are display text wearing a `check:` label.

**M5 — CDP tab hijack.** `_fetch_asset` (`oracle_mindset_context.py:1041-1047`)
grabs the first `"type": "page"` tab — the operator's live authenticated
browser — and `Page.navigate`s it. Session-riding surface + destroys the user's
open page. Same pattern in `oracle_scan.py` screenshot path. Fix: `Target.
createTarget` / `PUT /json/new`, never reuse a page tab. (LOGIC_AUDIT #3 theme,
unchanged.)

`_extract_handle_from_browser_profile` hardcodes
`/home/phantomcore/snap/chromium/common/chromium/Profile 2`; `tempfile.mktemp`

**L2 — Solidity seams get generic labels.** `_CLAIM_TYPE_REFLEX` has no `sol-*`

Add `sol-missing-guard`, `sol-reentrancy-shape`, etc. once H1 lands.

## What is genuinely strong (do not regress)

- `_run_check`: `shlex` + `shell=False`, curl-only, metachar-block, conn-hijack
  flags (`--resolve/--connect-to/--proxy…`), `-K 0600` secret config, tmp cleanup.
- 5-gate `verify_seam_card`: every gate proven to REJECT live (no-expected,
  no-source, ungrounded, out-of-scope) and to CONFIRM only on wire match.
- `_parse_seams` fail-closed on checks (no synthesis) + `_collect_recon`
  all-URLs-in-scope ingress filter.
- `_redact_creds` + `_redact_known_secrets` (verified working).
- `normalize_program_record` boundary (malformed → `None`).
- 121/121 tests green on a loopback suite with benign controls that must REJECT.

## Answer to "does it work on smart contracts as well as web2?"

No — not yet. Web2 has recon → templates → 5-gate verify → report, all live.
Smart contracts have: discovery records for Cantina/Code4rena/Sherlock/Immunefi,
`solidity_extractor` + `solidity_matcher` in the engine (proven: 1 PARADOX seam
on a NatSpec-guarded `withdraw` with the guard missing), and repo auto-clone —
but **no** template coverage (H1), **no** build/test/prove toolchain (H2),
generic labels (L2), and scope intake weakest exactly on web3 platforms (H5).
The path exists; the last mile (prove on-chain / on-fork) is missing.

## Appendix A — "shitty-code repos" test plan (no theft, no defacement)

The user asked: test Oracle against repos with initially-bad code, so we can
measure whether it finds issues — and where a found issue would defeat the
program's own purpose. Rules: local clones only, loopback/fork execution only,
no scanning or probing of live third-party deployments, no exfiltration, no
commit back to the repos. Read-only analysis + local proof.

**A1. Web2 bad-code fixtures (already in-repo — extend, don't replace).**
`tests/bad_code_app.py` (7 flaws) and `tests/vuln_testbed_full.py` (per-template
routes + benign controls on :8765) are the harness. Gaps to add as new routes:
POST-only state flaw reachable through the executor under a testnet flag (H3 —
currently unprovable by construction), a lookalike-host route
(`evil127 vs 127.0.0.1`) for the grounding gate, and an LLM-prose hallucinated
URL case for the IDOR gate (C1). Each new route gets a must-CONFIRM /
must-REJECT assertion in `test_golden_hunt.py`.

**A2. Smart-contract bad-code fixtures (new, small, local).**
Create `tests/fixtures/sol/` with 3 tiny contracts, each with a NatSpec guard
claim and the guard missing: `Vault.sol` (owner-only `withdraw`, no check),
`Price.sol` (stale-oracle `buy`, no staleness revert), `Vault2.sol`
(reentrant `withdraw`, state update after `call`). Plus one clean control
(`Guarded.sol` — guard present, must yield 0 seams). Assert: extractor fires on
the three, silent on the control; `forge build` green; `forge test` PoC
reproduces each (e.g. non-owner withdrawal succeeds); `anvil` fork-replay
optional second proof. This is the web3 mirror of the :8765 testbed.

**A3. Real-world repos (Aave V4 class, local clone, read-only).**
`targets/sherlock_aave_v4/` holds `scope.json` but no source checkout (my `find`
returned 0 `.sol` files under `targets/`). Clone the in-scope tag locally,
run the Solidity lens + new templates + slither/aderyn, and diff Oracle seams
against the contest's known findings set. Success metric is recall on known
issues with zero CONFIRMED-without-executed-proof — not novel zero-days on
someone else's live deployment. Record tool versions and commit hash in the
report so the run is reproducible.

**A4. "Defeats the program purpose" cases to include.**
For each fixture, tag the seam with the program rule it would break if live:
unauthenticated `withdraw` → fund-loss (contract's stated custody guarantee
void); stale-oracle `buy` → price-integrity guarantee void; trust-header admin
→ access-control guarantee void; debug-config credentials → secrecy guarantee
void. The report's impact line must name the defeated guarantee, not just the
bug class.
